# Canonical Paths — v6 Artifact Graph

**Mandatory input for every Phase 2 stack agent.** Use the paths declared here. Do not re-decide artifact placement during refactors. When a Phase 2 refactor surfaces a path conflict, stop and raise to operator — do not silently relocate artifacts.

This file inventories all 57 artifact paths produced by the 35 in-repo skills, locks the lifecycle taxonomy, resolves the `experience/` "split" diagnosis, and confirms top-level canonical folder ownership.

## Lifecycle taxonomy (locked from agent-skills/CLAUDE.md)

Authoritative source: [`agent-skills/CLAUDE.md` § "Lifecycle taxonomy"](../CLAUDE.md#lifecycle-taxonomy).

| Lifecycle | Where | Behavior |
|---|---|---|
| **canonical** | top-level (`brand/`, `architecture/`, `research/`) | Edited in place, kept forever, human-curated |
| **loop** | `skills-resources/loops/{slug}/program.md` | Operating contract for a measurable initiative |
| **loop-context** | `skills-resources/loops/{slug}/context.md` | Local assumptions, baselines, source links |
| **strategy** | `skills-resources/loops/{slug}/strategy/` | Loop-specific plans, hypotheses, briefs |
| **execution** | `skills-resources/loops/{slug}/execution/` | Publish-ready marketing/content assets |
| **evaluation** | `skills-resources/loops/{slug}/evals/` | Post-execution metric snapshots, scoring |
| **learning** | `skills-resources/loops/{slug}/learnings.md` | Promoted evidence-backed lessons for future cycles |
| **pipeline** | `.agents/skill-artifacts/{domain}/` | One-time skill output, regenerated by re-running |
| **decision** | `.agents/skill-artifacts/meta/decisions/` | Dated immutable record of strategic choice |
| **snapshot** | `.agents/skill-artifacts/meta/records/` | Dated point-in-time record |
| **ephemeral** | `.agents/skill-artifacts/.archive/` after cleanup | Working files; default cleanup target |

Plus working-draft types: **spec** (`.agents/skill-artifacts/meta/specs/`) and **sketch** (`.agents/skill-artifacts/meta/sketches/`) — neither immutable nor pipeline outputs.

## The `experience/` split — MIGRATED to `skills-resources/experience/`

**briefs.md §1.3 was correct: an experience/ split existed on disk. The first version of this file misdiagnosed it as resolved (claiming `skills-resources/experience/` was canonical and the brief was wrong) — that was caught by fresh-eyes review 2026-05-16. The actual resolution is migration to `skills-resources/experience/`.**

### What was actually on disk (2026-05-16, pre-migration)

Two parallel 9-file directories with identical layout:

- `skills-resources/experience/` — created May 16 by `bootstrap-experience.ts` during Phase 1C; one substantive file (`technical.md` with cleanup-artifacts excludes), 8 stubs
- `skills-resources/experience/` — pre-existing since May 15 with a richer README (the developed Q+A philosophy doc, May 5); 8 stubs + technical stub

The two locations did serve different scopes (cross-session knowledge vs loop-local learnings) — but briefs.md §1.3's call for path consolidation was right: maintaining both for the same Pre-Dispatch substrate creates drift. Pre-Dispatch protocol references inevitably point at one or the other and downstream skills inherit whichever cite they happen to load.

### Resolution (executed 2026-05-16)

**Canonical: `skills-resources/experience/`.** Rationale (operator decision):

- `CLAUDE.md` files are maintainer-only — they don't ship with `npx skills add`. The canonical experience/ location must be defined in **shipped** material (refs that propagate via `sync-skill-support.mjs`), not in CLAUDE.md.
- `skills-resources/` is the canonical home for shippable user-facing state (loops + experience); `.agents/` is the canonical home for machine-derived state (manifest + index + ephemeral artifact snapshots). Experience is user-facing append-only memory, not machine-derived index data.
- Migration cost was bounded: 48 canonical sources path-replaced via sed, then sync regenerated ~140 per-skill copies automatically. Single-session change.

### Actions taken

- Migrated `skills-resources/experience/technical.md` content → `skills-resources/experience/technical.md` (substantive cleanup-artifacts excludes preserved).
- Kept `skills-resources/experience/README.md` (the richer May-5 version) as canonical README.
- Path-replaced `skills-resources/experience/` → `skills-resources/experience/` across 48 canonical sources (5 existing refs, 3 new refs from Phase 1A/C, 22 SKILL.md files across 4 stacks, 3 scripts, 2 workflow-graph + cleanup-rules refs, 2 CLAUDE.md maintainer files, 1 README.md, 1 umbrella script).
- Re-ran `node scripts/sync-skill-support.mjs` — 140 per-skill `_shared/` + `scripts/` copies auto-regenerated with new path.
- Deleted `skills-resources/experience/`.
- `bootstrap-experience.ts` target dir updated to `skills-resources/experience/`; remains idempotent (won't clobber existing rich README).

### Distinction: what stays at `.agents/` vs moves to `skills-resources/`

| Stays at `.agents/` | Moves to `skills-resources/` |
|---|---|
| `.agents/manifest.json` (machine-derived index) | `skills-resources/experience/` (user-facing append-only memory) |
| `.agents/artifact-index.md` (human-readable selection map, derived) | `skills-resources/loops/[slug]/` (measurable initiative folders) |
| `.agents/skill-artifacts/` (one-shot pipeline outputs + records/decisions/sketches/specs) | |
| `.agents/skill-artifacts/.archive/` (ephemeral cleanup target) | |

The contract: `.agents/` is machine state. `skills-resources/` is user-facing state.

### Loop-local `learnings.md` remains separate (no conflict)

`skills-resources/loops/[slug]/learnings.md` is per-initiative cycle output (eval-loop-scoped). `skills-resources/experience/{domain}.md` is cross-session per-dimension knowledge (Pre-Dispatch-scoped). Same parent directory (`skills-resources/`), different scopes. Loop learnings can be promoted to experience/ via `[[promotion criteria]]` in `eval-loop-spec.md` (Phase 1D spec) — but the surfaces remain distinct.

## Lifecycle violations (⚠️) — fix during Phase 2 refactor

Marked with ⚠️ in tables above. Five issues to resolve.

### ⚠️ 1. Orchestrate-* state files claim `pipeline` but write to `skills-resources/experience/`

`orchestrate-{research,marketing,product,meta}` write `<stack>-workflow.md` to `skills-resources/experience/` — but `experience/` is per-dimension knowledge, not pipeline output. Two options:

- **(A)** Reclassify orchestrate-* workflow files as a separate dimension within `experience/` — keep path, change lifecycle to `experience` (new sub-type).
- **(B)** Move orchestrate-* workflow files to `.agents/skill-artifacts/meta/orchestrator-state/<stack>.md` — pipeline lifecycle stays accurate.

**Recommendation: (B).** State tracking ≠ Pre-Dispatch knowledge. Mixing them in `skills-resources/experience/` muddies the substrate that Pre-Dispatch reads.

(Now that experience/ is canonical at `skills-resources/experience/`, this violation persists post-migration — orchestrator workflow files still co-exist with Pre-Dispatch dimensions in the same directory. Phase 2 fix moves them out.)

### ⚠️ 2. `short-form-research` catalog labeled `pipeline` but used as reference

short-form-brief reads short-form-research's catalog as **reference material** (re-read across sessions), not as one-shot pipeline output. The lifecycle should be **canonical** (with `.agents/skill-artifacts/research/short-form-research/` as a sub-canonical location).

**Action:** Bump lifecycle to `canonical` during Phase 2 refactor; update artifact-index.md regen.

### ⚠️ 3. `eval-loop` dual-layer lifecycle undocumented

`eval-loop` is `standard` budget but its products carry their own per-artifact lifecycle tags (`loop`, `loop-context`, `strategy`, `execution`, `evaluation`, `learning`). The dual-layer is intentional but not documented in CLAUDE.md.

**Action:** Add a one-line note to `agent-skills/CLAUDE.md` § "Lifecycle taxonomy" — "Skills can carry skill-level budget while their per-artifact outputs carry per-artifact lifecycle (e.g., eval-loop)."

### ⚠️ 4. `docs-writing` lifecycle is ambiguous

docs-writing produces inline edits to existing docs (READMEs, CHANGELOGs, GitHub Release bodies). Its output is embedded, not standalone. Lifecycle: **ephemeral** (no tracked artifact) OR **inline-edit** (new sub-type).

**Recommendation:** Lifecycle `ephemeral` — its work product is the edit to the target file; no separate artifact persists.

### ⚠️ 5. results.tsv multi-writer pattern not formalized

`skills-resources/loops/[slug]/results.tsv` is written-to by `eval-loop` (initial scaffold), `short-form-eval` (per-cycle append), `lp-eval` (per-cycle append), and future `ad-eval` / `content-eval` / `campaign-eval`. Multi-writer is by design but no contract documents it.

**Action:** Add to `meta-skills/references/eval-loop-spec.md` — "results.tsv is multi-writer; each evaluator appends rows tagged by skill."

### ⚠️ 6. Stack CLAUDE.md files still contain full Complexity Routing (cascade pending)

Phase 1A trimmed the root `agent-skills/CLAUDE.md` § "Complexity Routing" from 26 lines to a 5-line summary + cite to `mode-resolver.md`. The same content remains duplicated in `meta-skills/CLAUDE.md`, `research-skills/CLAUDE.md`, `marketing-skills/CLAUDE.md`, `product-skills/CLAUDE.md`. Since CLAUDE.md files are maintainer-only (not shipped to users), redundancy is low-stakes but real drift risk.

**Action:** Cascade the same trim to the 4 stack-level CLAUDE.md files during Phase 2 (per-stack agent does it as a small in-session edit). Track here as pending.

## Provenance standard

For Gate 7 chain-hardening — when any artifact is extracted from or supersedes another, frontmatter MUST include:

```yaml
provenance:
  extracted_from: <path or section>
  extracted_at: YYYY-MM-DD
  supersedes: <prior artifact path>  # optional, when replacing
```

See [`meta-skills/references/artifact-contract-template.md`](../meta-skills/references/artifact-contract-template.md) § "Optional fields" for the full schema.

**When provenance is required:** any refactor-produced ref or canonical that derives from prior content (extraction, supersession, migration). The 7 Phase 1A/C refs all have it; this file has it; per-skill SKILL.md refactors should add it when extracting playbook content from existing body / refs.

**When provenance is optional:** original authored content with no prior source (most pipeline artifacts).

(The artifact-contract-template.md schema lists `provenance` under "Optional / context-dependent fields" because most artifacts don't need it. The refactor-context requirement above is canonical-paths-specific guidance for the v6 program, not a general schema requirement.)
