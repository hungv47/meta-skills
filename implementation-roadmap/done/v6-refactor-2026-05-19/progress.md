## Deferred ideas

Things noticed mid-program that are out of scope but worth remembering:

- **Harness v0.2 — mode flag auto-detection.** `record.ts --mode` is required to label runs as fast/standard/deep in JSON; without it everything reads `standard` regardless of the skill's actual path. Either (a) infer from fixture metadata (`expected_mode` field already in fixture frontmatter) or (b) instrument the skill to emit a "mode-resolved" event the hook can capture. Without this, cross-mode diff partition has to rely on `--by-notes` or `fixture_kind`.
- **Harness v0.2 — session-cache awareness.** Repeated invocations of the same skill within one Claude Code session under-count ref reads because the agent caches file contents in conversation context. Either (a) flag this in the JSON when ref load count is unexpectedly low, or (b) run baselines in a fresh `/clear`'d session per fixture for fairness. The diff numbers are still valid pre-vs-post for the same fixture; only cross-fixture comparisons within a session are affected.
- **Schema migration for custom results.tsv.** Stretch fixture surfaced that `append-loop-result.ts` validates an 8-col standard header but loops can request custom schemas (10+ cols). Either generalize the validator (read header from existing tsv) or accept hand-edit for non-standard loops. Out of refactor scope; flag for the eval-loop owner.
