# Structure Patterns — Write Longform

[PLAYBOOK] — the argument-structure library (outline agent) + prose craft (draft agent).

## Argument structures

Each is a spine — adapt it; don't fill it as a template.

### Thesis-defense
**Spine:** state the claim → 3 supporting moves (each a section) → address the strongest counter → reaffirm the claim, now earned → reader's next action.
**Use for:** opinionated pillars and essays where the value is the argument.

### Problem-mechanism-solution
**Spine:** the problem (specific, felt) → why it persists (the *mechanism* — the non-obvious reason; this is usually where the proprietary angle lives) → the resolution → how to apply it.
**Use for:** "how X really works" pillars. The mechanism section is what separates this from a generic problem/solution post.

### Frame-introduction
**Spine:** name the new frame/model (coin it if apt) → apply it to a concrete case → contrast with the old way of seeing it → the implications.
**Use for:** pieces whose originality IS a proprietary frame. The frame must be load-bearing, not a label on a generic argument.

### Comparative
**Spine:** the dimensions that actually matter (not the vendor feature grid) → option-by-option against those dimensions → the honest verdict (with "use X when..., Y when...").
**Use for:** "X vs Y" decision pillars. Honesty about tradeoffs is the credibility — a piece that declares one option universally best loses.

## Prose craft (draft agent)

### Openings
- **Open on the thesis + the stakes.** The first paragraph commits to the argument and tells the reader why it matters to them. No "in today's fast-paced world", no "in this post we'll cover".

### Paragraphs
- **One idea per paragraph**, topic sentence first.
- **No restatement.** A paragraph that says the prior one again in new words is cut.
- **Evidence shown, not asserted:** replace adjectives ("powerful", "seamless") with numbers, named examples, concrete scenarios.

### Transitions
- Each section's first sentence connects to the prior section's conclusion. The reader is carried, not dropped between headings.

### The proprietary angle
- It's the spine, not a garnish. Develop it across its section(s); make it the thing a reader screenshots or quotes.

### Conclusions
- **Resolve + act.** Restate the thesis as now-earned, then give the reader the specific next action. Don't trail off into a summary of what they just read.

## Search/AEO structure (SEO-anchored pieces only)

- **H2/H3 hierarchy maps to real sub-intents** (from the optimize-seo topic map if present), not a keyword list.
- **Answer-up-front block** for AEO: the direct answer to the page's core question in the first ~40–60 words, so answer engines can lift it. The argument still owns the rest.
- **Question headings** where they match how people search — but only when they also serve the argument's structure.
- **Never keyword-stuff.** Structure serves the reader and the answer engine simultaneously; if a heading exists only for a keyword, cut it.

## The necessity test (outline + critic)

For every section: mentally delete it. Does the argument weaken? If not, it's filler — cut it. Length is a *consequence* of a thorough argument, never a target the structure pads toward.
